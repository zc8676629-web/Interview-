# 本地面试工作台控制台化重构设计方案

日期：2026-08-25

## 1. 背景判断

当前前端已经具备完整业务路径：

1. 上传并分析简历
2. 沉淀面试场次
3. 沉淀高频问题
4. 管理本地设置和备份

但界面表达仍然偏向“功能卡片拼接”，主要问题不是功能缺失，而是：

1. 首页、导航、详情区的层级差异不够明显
2. 多个页面都采用相近灰卡片，控制台感不足
3. 关键动作、状态反馈、待处理事项没有被强调
4. 页面结构已经开始变复杂，但视觉语言还没有升级
5. 同一个系统里，上传、分析、复盘、整理看起来像几组独立模块，而不是同一套工作流

## 2. 本轮目标

本轮只做前端展示层重构，不改后端业务规则，不改 API 契约，不新增外部 UI 依赖。

目标是把当前页面升级成一版可直接演示、也适合继续迭代的 `专业控制台`：

1. 让用户一眼看出当前状态、关键数据和下一步动作
2. 让左侧导航真正承担“模块切换 + 状态索引”的职责
3. 让总览、简历、场次、高频题、设置五个页面形成统一视觉体系
4. 保持中文长文本可读性，不为了“后台感”牺牲实际阅读体验
5. 保持轻量和本地优先，不走重动画和重装饰路线

## 3. 设计方向

### 3.1 产品气质

定位为 `本地面试作战台`，而不是普通后台模板或一次性 Demo。

它应该传递三层感觉：

1. 这是一个长期管理系统
2. 这是一个强调执行效率的工作台
3. 这是一个以本地数据为核心的个人控制台

### 3.2 视觉语言

采用 `青绿主色 + 橙色动作色 + 大面积浅底 + 深色文本` 的控制台风格。

- 青绿：承载品牌识别、导航激活、关键状态、重点数字
- 橙色：只给真正需要推动的动作，例如生成、开始分析、保存确认
- 浅底与白卡片：保证中文长文本的连续阅读舒适度
- 深色文本与边框：建立专业、克制、可靠的感受

不再依赖大面积深灰渐变和“玻璃感”来制造高级感，重点改为：

1. 更强的区块层级
2. 更稳定的间距系统
3. 更明确的主次按钮关系
4. 更清晰的状态反馈和数量表达

## 4. 信息架构重排

### 4.1 全局外壳

整体页面分成三层：

1. 顶部控制台总头部
2. 左侧工作台导航
3. 右侧主工作区

顶部总头部负责展示：

- 系统标题
- 当前状态消息
- 本地优先说明
- 全局关键指标

左侧导航负责展示：

- 工作台定位说明
- 五个模块入口
- 每个模块的摘要数量或状态提示
- 当前运行状态

右侧主工作区负责承载当前页面内容，所有页面共享相同的节奏：

1. 页面标题区
2. 动作区
3. 摘要区
4. 内容区

### 4.2 页面导航结构

保留现有五个入口，不改业务含义：

1. 作战总览
2. 简历分析
3. 面试场次库
4. 高频问题库
5. 系统设置

但导航样式改为：

- 左侧序号 + 主标题
- 右侧数量或状态
- 激活页显示强对比底色和边框
- 非激活页仍保留足够可点击感

## 5. 页面级方案

### 5.1 作战总览

目标不是“展示很多卡片”，而是“告诉用户系统现在处于什么状态”。

页面分为四段：

1. 顶部总览条
2. 当前优先事项
3. AI 备战建议
4. 全局检索

其中：

- 顶部总览条用更紧凑的指标卡表达数量与变化重点
- 当前优先事项使用更强的动作卡，强调“下一步去哪里”
- AI 备战建议作为主卡片，承担最重要的分析输出
- 全局检索以两栏或三栏结果区承载命中内容

### 5.2 简历分析页

简历页需要从“设置卡 + 上传卡 + 结果卡”升级成一个完整流程页：

1. 顶部先展示当前工作模式和简历处理入口
2. 中部左侧是简历版本列表
3. 中部右侧是当前简历画像、预测问题和回答生成

模型与连通性设置在这里应保持 `紧凑版` 展示，只保留必要操作，不再抢主视觉焦点。

### 5.3 面试场次库

场次页是内容密度最高的页面之一，需要明显区分：

1. 左侧场次列表
2. 右侧场次详情
3. 顶部操作条
4. 分类筛选

重点提升：

- 当前选中场次更容易识别
- 批量动作更像工具栏，而不是普通按钮行
- 问题卡片中“选择 / 编辑 / 回答稿 / 标签”的层级更清楚

### 5.4 高频问题库

高频题页面要体现“沉淀后的管理中心”，而不是普通列表。

重构后应突出：

1. 置顶问题优先级
2. 来源场次与标签关系
3. 回答稿是否已准备
4. AI 去重候选的可读性

页面结构保持“主列表 + 辅助区块”，但通过更清楚的卡片头部、元信息和状态标签来提升管理感。

### 5.5 系统设置

设置页需要与业务页明显区分，强调它是控制台后台区：

1. 左侧：本地设置与声明
2. 右侧：备份、导入导出、清空操作、回收站

危险操作与普通操作要有更强的视觉隔离，避免所有按钮看起来权重接近。

## 6. 组件与样式规则

### 6.1 设计 Token

本轮统一使用 CSS 变量管理：

1. 颜色
2. 间距
3. 圆角
4. 阴影
5. 边框
6. 动效时长

页面和组件不再散落使用大量裸十六进制值。

### 6.2 卡片体系

卡片分为四类：

1. 主面板卡
2. 指标卡
3. 操作卡
4. 内容卡

通过背景、边框、间距和标题权重区分，而不是只靠尺寸差异。

### 6.3 按钮体系

按钮分四级：

1. 主动作按钮
2. 次动作按钮
3. 轻量按钮
4. 危险按钮

所有页统一颜色、悬停、禁用和焦点表现。

### 6.4 文本体系

中文正文优先考虑长阅读舒适度：

- 主体文字 16px 左右
- 行高 1.6 左右
- 标题层级明确
- 数字指标使用更稳定的字重和对齐

### 6.5 交互与可访问性

本轮必须明确补齐：

1. 可见焦点态
2. 跳到主内容入口
3. 页面结构化标题层级
4. 键盘可达性不退化
5. `prefers-reduced-motion` 支持

## 7. 不改的部分

本轮明确不做：

1. 后端接口结构重写
2. 新增图表系统
3. 引入外部组件库
4. 深色模式
5. 新页面和新业务能力
6. 大规模拆分现有业务组件逻辑

## 8. 测试重点

需要重点验证：

1. 顶部头部、左侧导航和主工作区仍可正常切换
2. 作战总览仍能显示指标、待办和搜索结果
3. 简历分析页的主简历切换与预测题回答不受影响
4. 面试场次库的新建、筛选、编辑仍可用
5. 高频问题库的置顶、编辑、删除仍可用
6. 设置页的免责声明、本地数据管理和回收站仍可见
7. 样式层不引入性能守卫禁止的写法

## 9. 结论

这次重构的本质不是“换一套颜色”，而是把现有功能重新组织成一套真正像控制台的前端表达：

1. 顶层外壳更稳定
2. 导航承担索引作用
3. 页面层级更清晰
4. 关键动作更突出
5. 本地面试工作台的产品感更完整
