# 本地面试工作台成熟度升级设计方案

日期：2026-08-21

## 1. 背景判断

当前 Demo 已经具备三类基础能力：

1. 简历分析与个人画像
2. 面试场次沉淀
3. 高频问题沉淀

但如果按“长期持续使用的本地应用”标准看，核心短板已经不是“有没有更多按钮”，而是：

1. 数据越来越多以后，没有一个总览页告诉用户现在最该做什么
2. 场次、问题、高频题分散在多个页面里，缺少统一检索入口
3. AI 目前主要用于单点生成，缺少对全局数据的复盘和优先级建议
4. 本地数据虽然自动保存，但缺少明确的备份与恢复路径
5. 页面在数据变多时容易变成长列表，操作成本和滚动成本都会升高

## 2. 本轮目标

本轮不做“大而全重构”，只做第一阶段最值钱的四件事：

1. 新增 `作战总览` 页面
2. 新增 `AI备战建议`
3. 新增 `全局检索`
4. 新增 `本地备份导入导出`

目标是让这个 Demo 从“能用”变成“开始适合长期用”。

## 3. 现阶段痛点

### 3.1 用户侧痛点

- 打开应用后，看不到当前缺什么、先做什么
- 高频问题越来越多后，很难快速找到某题来自哪一场面试
- 已经有简历分析、场次和题库，但系统不会自动告诉用户优先准备什么
- 一旦误删、换机、重装系统，没有明确的数据迁移方案

### 3.2 AI 侧痛点

- AI 只在“提问题”和“答问题”两个点上发挥作用
- 没有把简历画像、真实面试记录、高频题库三类数据串起来
- 没有把 AI 用在“下一步行动建议”上

### 3.3 体验侧痛点

- 数据列表增长后，信息层级不够清晰
- 缺少统一搜索入口
- 缺少对本地数据安全感的明确表达
- 页面缺少“我现在应该去哪”的导航感

## 4. 方案概览

### 4.1 新增作战总览

在左侧导航顶部新增 `作战总览`。

这个页面承担四个职责：

1. 展示关键数量概览
2. 汇总待处理事项
3. 提供统一检索入口
4. 承载 AI 备战建议

### 4.2 新增 AI 备战建议

新增一个面向全局数据的 AI 能力：

- 输入源不是单个问题，而是：
  - 最新简历画像
  - 面试场次库
  - 高频问题库
- 输出不是单题回答，而是：
  - 当前最该优先准备的方向
  - 哪些问题重复出现
  - 哪些题还没有合适答案
  - 接下来建议补什么

输出要偏执行，不写空话。

### 4.3 新增全局检索

在作战总览提供一个搜索框，支持跨以下内容检索：

- 面试场次标题
- 面试问题文本
- 问题标签
- 高频问题文本
- 高频问题标签

结果按两组展示：

1. 命中的面试场次
2. 命中的高频问题

这样用户不需要在多个页面来回翻。

### 4.4 新增本地备份导入导出

新增本地数据管理能力：

- 导出当前本地数据为 JSON 备份文件
- 导入之前导出的备份文件并恢复数据

默认导出：

- 简历分析
- 面试场次
- 高频问题
- AI 去重候选
- AI 备战建议
- 当前模型选择

默认不导出 API Key，避免明文泄漏风险。

## 5. 页面设计

## 5.1 导航结构

调整后左侧导航为：

1. 作战总览
2. 简历分析
3. 面试场次库
4. 高频问题库
5. 系统设置

## 5.2 作战总览布局

页面由四块组成：

### A. 顶部概览卡

展示：

- 简历分析数
- 面试场次数
- 高频问题数
- 已有回答数
- 待补回答数

### B. 当前待办卡

根据本地数据给出清晰提示，例如：

- 还没有简历画像
- 某些高频题还没有回答
- 已识别到待确认的重复题

### C. 全局检索区

支持输入关键词后直接展示命中结果。

### D. AI 备战建议区

按钮：

- `生成 AI 备战建议`

卡片内容：

- 当前重点准备方向
- 近期高频风险点
- 建议先补的题
- 下一步行动清单

并显示生成时间，结果持久保存。

## 6. 数据设计

### 6.1 新增 AI 备战建议记录

新增字段结构：

- `generatedAt`
- `summary`
- `priorities`
- `coverageGaps`
- `nextActions`

这份数据只保留最新一份即可，不需要做版本历史。

### 6.2 导出结构

导出文件包含：

- `version`
- `exportedAt`
- `snapshot`

其中 `snapshot.settings.apiKey` 为空字符串。

### 6.3 导入规则

- 仅接受本应用导出的结构
- 导入后整体替换本地业务数据
- 若导入文件未包含 API Key，则保留当前本地 API Key

## 7. AI 输出要求

### 7.1 AI 备战建议

必须满足：

- 基于已有本地事实，不编造经历
- 偏执行，不空泛
- 中文自然表达
- 输出结构稳定，便于前端拆分展示

建议输出结构：

- `summary`
- `priorities`
- `coverageGaps`
- `nextActions`

## 8. 第一阶段不做

- 云同步
- 多设备自动合并
- 真正的向量语义检索
- 练习模式和打卡系统
- 高频问题多轮版本管理
- AI 自动帮用户合并问题

## 9. 测试重点

需要重点验证：

1. 导航中出现 `作战总览`
2. 作战总览可展示核心指标
3. 全局检索可跨场次和高频题生效
4. AI 备战建议可生成并持久保存
5. 导出结果不包含 API Key
6. 导入后数据可恢复

## 10. 结论

这一轮最关键的成熟度提升，不是继续堆页面，而是把已有数据组织成“能指导行动”的系统：

- 用 `作战总览` 解决看全局
- 用 `AI 备战建议` 解决下一步做什么
- 用 `全局检索` 解决数据变多后怎么找
- 用 `本地备份导入导出` 解决长期使用的安全感
